# Contributing to VanUikit

Thanks for your interest in contributing! This guide covers how to set up the
project, run checks, and propose changes.

## Prerequisites

- [Bun](https://bun.sh/) (used for install, tests, and scripts)
- [Node.js](https://nodejs.org/) 20+ (some tooling and the docs build run on Node)
- Git

## Setup

```bash
git clone https://github.com/JonnyRodriguez/vanuikit.git
cd vanuikit
bun install
```

The repo is a workspace with three packages:

| Path | Purpose |
|---|---|
| `vanuikit/` | The library published to npm (`vanuikit`). |
| `demo/` | Demo SPA + Hono server consuming the library (workspace). |
| `docs-site/` | Starlight documentation portal generated from `vanuikit/docs/`. |

Install docs-site dependencies separately when working on the portal:

```bash
bun install --cwd docs-site
```

## Common commands

From the repo root:

| Command | What it does |
|---|---|
| `bun run build` | Build the library (`vanuikit/dist`). |
| `bun run test` | Run library tests (`vanuikit/tests`, via `bun test`). |
| `bun run lint` | Typecheck (library + demo), i18n gates, and spelling. |
| `bun run dev` | Run the demo dev server. |
| `bun run docs:sync` | Regenerate `docs-site/src/content/docs/` from `vanuikit/docs/`. |
| `bun run docs:dev` | Local Starlight docs server. |
| `bun run docs:build` | Build docs + the static component playground into `docs-site/dist/`. |

From `vanuikit/`:

| Command | What it does |
|---|---|
| `bun run typecheck` | Typecheck the library. |
| `bun test` | Run the test suite. |
| `bun run check:van` | VanJS reactivity static scan. |
| `bun run size` | Size budget check over `dist/index.js`. |
| `bun run build` | Build CSS, bundles, and types. |

## Project conventions

- **Commit messages in English.**
- **Canonical docs source:** edit `vanuikit/docs/**` (and package docs like
  `vanuikit/README.md` / `CHANGELOG.md` as appropriate). `docs-site/src/content/docs/`
  is generated by `docs:sync` — do not edit it by hand.
- **Single VanJS instance:** consumers import `van` from `vanuikit`, not from
  `vanjs-core` directly. Keep this rule intact in examples and demo code.
- **Reactivity and i18n rules:** follow [`AGENTS.md`](./AGENTS.md) and
  [`vanuikit/docs/DEBUG_REACTIVITY.md`](./vanuikit/docs/DEBUG_REACTIVITY.md)
  (container rule, hoist `t()`/`fmt.*()` states, no node-valued states, etc.).
- **UI text:** user-visible strings use `t()`/`raw()` with semantic keys and
  English inline defaults; Spanish/French live in translation dictionaries.

## Definition of Done (components / changes)

Before considering a component or user-facing change complete:

1. **Implementation** in `vanuikit/src/` with a reactive API consistent with the
   existing catalog (accept `State` where visual props are reactive).
2. **i18n:** visible text via `t()`/`raw()` (no hardcoded user strings); update
   locales as needed (`i18n:collect` / gates).
3. **Tests:** unit tests in `vanuikit/tests/` (`bun test`).
4. **Demo:** showcase real usage in `demo/pages` when applicable.
5. **Styles:** use `--vui-*` tokens / existing conventions (no hardcoded colors
   that bypass theming).
6. **Quality gates:** `bun test` green, typecheck clean, and relevant gates
   (`lint`, `check:van`, `size`, docs build) passing.
7. **Exports & docs:** export from `vanuikit/src/index.ts` when public, and
   update the catalog/docs/changelog as appropriate.

## Pull requests

- Keep changes focused and describe the motivation and behavior.
- Include screenshots or recordings for UI changes when helpful.
- Link related issues.
- Make sure CI passes (typecheck, tests, size, language gates, docs build).

By participating, you agree to follow the [Code of Conduct](./CODE_OF_CONDUCT.md).
